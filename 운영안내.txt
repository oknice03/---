PPT BRANDING 홈페이지 운영 안내
검수 버전: 2026-10-27-portfolio-v5-search-ready
검수 상태: 로컬 검수 완료. 실제 공개 여부는 GitHub 커밋·Netlify 배포 결과와 공개 URL로 확인합니다.

1. 대표님이 새 포트폴리오를 추가할 때
사진과 아래 내용을 이 대화에 보내주시면 새 상세 페이지로 정리할 수 있습니다.
- 공개 가능한 프로젝트명(실명 공개가 어렵다면 업종명)
- 업종과 사용 목적
- 고객의 실제 요청
- 실제 진행한 기획·디자인 작업
- 공개 가능한 표지·내부 페이지 이미지와 이미지별 설명
- 공개해도 되는 범위, 가려야 할 정보
고객의 효과·성과·만족도는 확인된 내용이 있을 때만 씁니다.
총 31개 사례 중 5개는 공개 제작기에 근거한 진행 이야기와 선별 실제 페이지 17장을 담았습니다. 나머지 26개는 기존 공개 이미지에서 확인되는 디자인 설명입니다.
실제 페이지는 사례마다 대표 3~4장만 선별하며 반복 페이지·수치표·증빙 전체를 모두 올리지 않습니다.
민감 정보는 공개용 사본에 작은 영역만 가리고 표지·로고·배치는 유지합니다. 원본은 보존합니다.
고객 요청, 계약 범위, 제작 연도, 성과를 임의로 만들어 넣지 않았습니다.

2. 현재 페이지 구성
회사소개서: 메인 /portfolio/ 사례목록 + 상세15 /guides/ 안내목록 + 안내3 /about/ /services/
공사지명원: 메인 /portfolio/ 사례목록 + 상세16 /guides/ 안내목록 + 안내3
총 45개 색인 후보 주소입니다. 404·인증 파일·llms.txt는 사이트맵의 페이지 목록에서 제외합니다.
두 사이트에 함께 있었던 6개 건설 관련 이미지는 공사지명원 상세 페이지에만 설명을 두고 회사소개서 목록에서 연결합니다.
기존 도메인, 루트 메인 주소, 주요 섹션 앵커와 검색 소유권 인증은 유지합니다. 가림 전 이미지는 공개용 사본 또는 표지로 교체했습니다.
주소를 새로 만드는 데 별도 도메인 구매가 필요하지 않습니다.

3. 개발·수정 방법 (담당자용)
Node.js 20 이상이 필요합니다. Netlify는 Node 22 설정입니다. 유료 라이브러리·CMS·데이터베이스는 없습니다.
실행 위치는 이 안내 파일이 있는 Git 프로젝트 폴더입니다.

npm run new-case -- 영문-사례주소
→ content/cases/영문-사례주소.json 초안이 생깁니다. 기존 파일은 덮어쓰지 않습니다.
→ 제목, 업종, 요약, 본문, 이미지 목록, 출처·공개 검토 근거, 수정 날짜를 작성합니다.
→ 이미지는 assets/img/portfolio/ 안에 넣습니다. JPG/PNG/WebP 사용.
→ 대표 3~4장을 images에 넣습니다. storyKind: production 사례는 sources·facts와 함께 본문 sections.image에 이미지 번호를 지정해 설명과 교차 배치합니다.
→ 가림 전 이미지 차단 목록은 content/image-privacy.json입니다. 이미지를 다시 잘못 연결하면 빌드가 실패합니다.
→ assets/img/cases/는 공개 검수한 파일만 .gitignore의 예외 목록에 넣어 GitHub에 전송합니다. 새 이미지를 이 폴더에 넣었다면 공개용 사본인지 검토하고 예외 목록도 갱신하세요. 원본·미선별 이미지·초안 자료는 공개 저장소에 올리지 않습니다.
→ status: draft는 배포 결과·사이트맵·llms.txt에서 제외됩니다.
→ 본문·공개 범위 검토를 마친 항목만 status: ready로 바꿉니다.
  ready는 배포 후보라는 뜻이며 대표의 공개 승인이나 배포 완료를 뜻하지 않습니다.
→ order 숫자가 작을수록 먼저 표시됩니다. 메인에는 상위 6개를 노출합니다.
→ updated는 내용이 실제로 수정된 날짜(YYYY-MM-DD)입니다.
→ 발행한 slug는 임의로 바꾸지 않습니다. 주소 변경이 필요하면 이전 주소 리다이렉트도 설계해야 합니다.

npm run build
→ dist/에 공개용 정적 HTML을 만듭니다. 목록, 관련 사례, 검색용 구조화 데이터, 사이트맵과 llms.txt도 갱신합니다.
→ index.html은 메인 문구·서비스·검색 제목·소개글의 편집 원본입니다. FAQ는 content/faq.json이 화면과 구조화 데이터의 단일 원본입니다.
→ 메인 메뉴, 포트폴리오 섹션, 하단 메뉴는 빌드 시 생성기로 치환됩니다.
→ 새 포트폴리오는 원본 index.html의 옛 이미지 목록에 넣지 말고 JSON에 추가합니다.
→ 기존 사례는 content/cases.json, 새 개별 사례는 content/cases/*.json에서 관리합니다.
→ content/guides.json: 제작 안내 내용 / content/site.json: 도메인과 서비스 기본 정보
→ content/related.json: 다른 서비스의 관련 사례 링크(직접 관리, 두 저장소 간 자동 동기화 아님)
→ 다른 서비스의 관련 링크를 추가·변경했다면 두 사이트를 함께 검사하세요.
→ scripts/build.mjs, css/pages.css, js/pages.js가 두 저장소에 동일한 공통 구현입니다.
→ 공통 화면을 바꿀 때는 두 저장소에 같이 적용하고 검증하세요.

npm run check
→ 내부 링크, 고유 제목·소개글·canonical, 사이트맵, JSON-LD, H2, FAQ 데이터 일치, 이미지 설명, 가림 전 이미지 제외, llms.txt 동기화와 소유권 인증 보존을 검사합니다.
→ PEER_DIST 환경변수에 다른 사이트 dist 절대 경로를 지정하면 두 사이트 사이의 링크도 검사합니다.

npm run preview
→ 이 컴퓨터의 http://127.0.0.1:4173 에서 미리 봅니다.
→ 다른 사이트도 동시에 볼 경우 PORT 환경변수에 다른 포트를 지정합니다.
→ 검수 서버는 색인 금지 헤더를 보냅니다.
→ 중지: 실행한 터미널에서 Ctrl+C.
→ dist 파일을 직접 수정하면 다음 빌드 때 덮어씁니다.

4. 승인 후 배포 절차
- 대표가 사례 문구·공개 범위와 화면 버전을 확인합니다.
- Netlify 계정의 현재 플랜·남은 크레딧·자동 충전 상태를 확인합니다.
- 두 사이트의 관련 페이지가 동시에 연결되도록 함께 배포를 준비합니다.
- 이번 수정 파일만 해당 Git 저장소에 커밋·푸시합니다. 회사소개서 폴더의 기존 시장조사 자료는 포함하지 않습니다.
- Netlify의 빌드 명령은 npm run build, 배포 폴더는 dist 입니다.
- 서버 루트나 소스 폴더 전체를 드래그해서 배포하지 않습니다.
- 제작 원본/PDF/ZIP/이력서/내부 자료는 배포 대상에서 제외됩니다. 빌드 출력은 허용된 정적 파일만 담습니다.
- 대표 승인 전에는 GitHub push, Netlify deploy, DNS 변경을 하지 않습니다.
- 배포 후 실제 HTTPS 주소, 이미지, 서로 연결한 링크, 404 응답과 사이트맵을 재검사합니다.
- 두 도메인의 기존 Search Console/네이버 등록 속성과 사이트맵을 확인하고 필요하면 재제출합니다.
  포트폴리오 페이지마다 별도 사이트 소유권 등록을 하는 방식이 아닙니다.
- 새 대표 사례의 URL 검사를 진행합니다. 검색 색인과 AI 답변 노출은 별개이며 확정되지 않습니다.
- 공개 배포는 대표 승인 범위에서만 진행하며 도메인·결제 설정 변경은 별도 승인 대상입니다.

5. 비용과 AI 검색
이 확장에는 유료 CMS, SEO 플러그인, AI API, 데이터베이스가 필요하지 않습니다.
기존 도메인 갱신과 호스팅 이용 조건은 계속 적용됩니다.
2026-10-27 공식 크레딧 요금제 안내 기준:
Free 월 300크레딧 / Personal 월 $9, 1,000크레딧.
정식 배포 성공 1회 15크레딧. 두 사이트를 한 번씩 배포하면 배포분만 30크레딧입니다.
여러 페이지를 한꺼번에 배포하면 페이지마다 15크레딧이 붙는 것이 아닙니다.
방문 트래픽·이미지 전송량 등은 별도로 크레딧을 사용합니다.
유료 플랜의 자동 충전을 켜면 추가 결제가 가능하며, 꺼두면 한도 소진 시 사이트가 일시 중단될 수 있습니다.
기존 계정이 레거시 플랜이면 다를 수 있습니다. 이 작업에서는 계정 청구 화면을 확인하지 않았습니다.
구매, 업그레이드, 자동 충전 설정 변경은 하지 않았습니다.

AI에 잘 읽히도록 정적 본문, 사례별 주소, 관련 링크, 브랜드 식별 정보와 사이트맵을 준비했습니다.
robots.txt의 기존 전체 허용 정책을 유지했습니다. 검색봇 접근 허용은 노출을 보장하는 장치가 아닙니다.
일반 검색과 AI 답변에 반드시 선택되거나 특정 순위에 나온다는 보장은 없습니다.
실제 고객 과제·작업 범위·검증된 결과를 이후 보완하면 단순 이미지 설명보다 구체적인 근거를 제공할 수 있습니다.
릴스 요청에 따라 llms.txt를 선택적 공개 요약 파일로 추가했습니다. 필수 등록 파일이나 AI 추천 보장 장치는 아닙니다. 별도 유료 서비스는 추가하지 않았습니다.

6. 이번 검색 등록 상태 확인 (2026-10-27)
- 구글: 두 도메인 모두 기존 등록과 /sitemap.xml 성공 상태 확인. 배포 전 확인 당시 각각 발견된 페이지는 1개였으며, 새 페이지의 수집·색인 상태는 배포 후 별도로 확인해야 합니다.
- 네이버: 소유권 확인 메타는 보존했습니다. 현재 브라우저에서 로그인이 필요해 관리 화면 상태는 재확인하지 못했습니다.
- 공개 승인·배포 뒤 기존 등록 속성에서 사이트맵을 확인하고 새 사례 URL을 검사합니다. 기존 RSS나 다른 속성을 임의로 삭제하지 않습니다.
